# 05. 운영 로직 및 비즈니스 정책

## 5.1 핵심 비즈니스 규칙

### BR1. 학습효과 우선

게임화 메커닉이 학습효과 측정과 충돌하면 학습효과를 우선한다. 예: "스트릭이 끊기면 사용자 이탈"이 아니라 "스트릭 자체가 자기효능감을 깎으면 스트릭을 없앤다."

### BR2. 외재 보상 최소화

V1은 XP/레벨까지만. 그 이상의 보상 레이어(배지, 칭호, 가상화폐) 추가 시 명세 작성자 동의 필요.

### BR3. PVE만 허용

또래 비교 메커닉(랭킹, 매칭, 친구 도전, 점수 비교) V1에서 모두 금지. 본인 vs 본인 기록만 허용. SNS 공유는 자랑이 아닌 "같이 해보자" 톤.

### BR4. 5문제 1세션 고정

V1 한 세션 = 5문제. 시간 제한 X. 한 카드 풀이 시간은 무제한.

### BR5. FSRS가 카드 출제 결정자

사용자가 "어떤 카드 풀지" 선택 X. FSRS 우선순위 큐가 자동 결정. 단, 빈 큐 시 데모 모드 진입은 사용자 선택.

### BR6. 정답 판정은 equivalent form 인식

`x(2x+7) + 3` 같은 부분 변형도 인수분해 합법 경로면 정답 처리. AST 기반 equivalent form 매칭.

### BR7. Kill / Pivot 판정 (6주 시점)

V1 출시 후 6주에 4 신호 + 학습효과 신호 측정:
- 4 신호 중 3개 이상 + 학습효과 신호 통과 → V2 진입
- 4 신호 중 2개 또는 학습효과 신호 실패 → Pivot (메커닉/콘텐츠 변경)
- 4 신호 중 1개 이하 → Kill (명제 자체 재검토)

## 5.2 Auth / ACL 정책 (V1)

### 인증

- **V1 = 비로그인**. 사용자 식별은 browser fingerprint (UUID 기반 + canvas/font 보조 신호)
- 시크릿 모드, 브라우저 클리어 = 새로운 사용자로 인식 (silent failure 위험)
- 로그인/회원가입 화면 V1에 없음

### 데이터 접근 제어

- 모든 카드 풀, 5문제 시퀀스 = public (비로그인 누구나 접근)
- 본인 fingerprint 기반 진행도 = 같은 브라우저 세션 내에서만 조회
- 다른 사용자 데이터 조회 API 없음

### V2 확장 (메모용, V1 구현 X)

- Magic link 옵션 (이메일 1회 입력) → fingerprint와 합쳐 retrieval 데이터 보존
- 풀림 SSO 통합 → 풀림 계정과 fingerprint sync
- B2B 학교 도입 시 학교/학원 단위 인증

## 5.3 ERD / 데이터 모델

### Card (카드 마스터)

```
Card {
  id: UUID (PK)
  type: "factorization-block"   // V1 단일 type
  problem: {
    polynomial: string           // "2x² + 7x + 3"
    ast: PolynomialAST          // 파싱된 트리
    target_form: "factored"
  }
  difficulty_seed: 1..5          // 콘텐츠 큐레이터 할당
  unit: string                   // "고1-인수분해-공통인수"
  created_at: timestamp
  updated_at: timestamp
}
```

V1 = 5장 카드 (난이도 1~5 시드)
저장 = static JSON (V2부터 Vercel KV 마이그레이션 검토)

### CardState (사용자별 카드 상태)

```
CardState {
  fingerprint: string (PK1)
  card_id: UUID (PK2, FK → Card.id)
  R: float                       // retrievability 0~1
  S: float                       // stability (days)
  D: float                       // difficulty 1~10
  last_review_at: timestamp
  review_count: integer
  outcome_history: array         // ['pass', 'pass', 'fail', ...]
}
```

저장 = client-side localStorage (V1) + 서버 백업 (Vercel KV, V2)

### Session

```
Session {
  id: UUID (PK)
  fingerprint: string            // 익명 식별자
  started_at: timestamp
  ended_at: timestamp | null
  card_ids_attempted: UUID[]     // 5문제 시퀀스
  outcome: 'completed' | 'abandoned' | 'in_progress'
}
```

저장 = client-side + 서버 이벤트 로그

### Event (익명 이벤트 로깅)

```
Event {
  id: UUID (PK)
  session_id: UUID (FK)
  fingerprint: string
  card_id: UUID | null
  action: 'drag-start' | 'drag-end' | 'transform' | 'submit' | 'abandon'
  timestamp_ms: integer
  payload: JSONB                 // 인터랙션 정확도 측정용 (좌표, 시간 등)
}
```

저장 = `/api/event` POST → Vercel KV 또는 별도 분석 DB. PII 0.

## 5.4 Validation Rules

| 입력 | 검증 규칙 | 위반 시 |
|---|---|---|
| 카드 JSON 로드 | Zod 스키마 (id, type, problem, difficulty_seed) | 명시 에러 + 로깅 + fallback UI |
| 이벤트 payload | Zod 스키마 (action enum, timestamp_ms 양수, fingerprint format) | 422 응답 + 로깅 |
| Fingerprint format | UUID v4 또는 보조 신호 hash | 새 fingerprint 자동 생성 |
| AST 변형 결과 | round-trip 검증 (변형 후 다시 expand하면 원본 다항식과 equivalent) | 정답 인정 X, 재시도 가능 |
| 카드 difficulty_seed | 정수 1~5 | 카드 로드 거부 (콘텐츠 큐레이터 알림) |

## 5.5 데이터 보존 정책

- **익명 이벤트 로그**: 6개월 보존 후 자동 삭제 (V1 분석 기간 + 마진)
- **카드 마스터**: 영구 보존
- **CardState (localStorage)**: 사용자가 브라우저 클리어 시 자동 삭제
- **Session**: 6개월 보존

## 5.6 PII 정책 (V1)

- **수집 항목 0개.** 이름, 이메일, 전화번호, 학교, 학년 모두 수집 X
- **저장 항목**: browser fingerprint (보조 신호 포함), 인터랙션 좌표, 풀이 결과
- **만 14세 미만 처리**: V1 비로그인이라 정통망법 적용 안 됨. 로그인 도입 시 재검토
- **GDPR/CCPA**: 한국 서비스라 1차 적용 대상 아님. 글로벌 확장 시 재검토

### 출시 알림 신청 (V1.5 — Plan D Phase 2)

- 이메일 원문 저장 금지. 클라이언트가 입력한 이메일을 받는 즉시 **SHA-256 hash 만 저장**. plain email 은 서버 메모리·로그 어느 곳에도 남기지 않는다 (`/api/billing/notify` 라우트가 hash 만 받는 구조).
- 보존 기간 **6개월** (익명 이벤트 로그와 동일 정책).
- 동일 hash 중복 신청은 동일 식별자로 dedupe — 신청 횟수만 카운트.
- 사용자 안내 카피: "출시 시 알림을 받기 위해 신청됐어요. 입력한 이메일은 해시(hash) 처리되어 저장되고, 출시 알림 발송 외 용도로는 사용하지 않으며 6개월 후 자동 삭제됩니다."

- **BR-PAY1 학습효과 잠금 금지**: 학습효과를 직접 결정하는 기능 (FSRS 큐, 정답 판정, 5문제 룰 BR4) 은 유료 잠금 대상이 아니다. 콘텐츠량·편의 기능·분석 깊이만 잠금 대상.
- **BR-PAY2 다크 패턴 금지**: 자동 갱신 알림은 갱신일 7일 전 이메일 1회 + 결제일 영수증 1회. 결제 취소 UI 는 결제 신청 UI 와 동일 깊이로 노출 (해지 숨김 금지).
- **BR-PAY3 학생 보호**: 만 14세 미만 결제 0 (정통망법). 만 18세 미만 결제 시 보호자 동의 절차 필수 — V2 진입 시 별도 명세 (현재 V1 비로그인이라 N/A).
- **BR-PAY4 가격 인상 정책**: 기존 구독자는 최소 6개월 그래퍼더링 (현 가격 유지). 신규 가입자만 신가격 적용. 가격 인상 통보 30일 전 이메일·앱 내 공지.
