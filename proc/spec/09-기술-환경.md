## 9.2 라이브러리 결정 — Build vs Buy

### 9.2.1 인터랙티브 수식 렌더 (1주차 결정)

**옵션 A — 자체 SVG 컴포넌트 (Build):**
- 장점: 정확한 hit area 제어, 디자인 시스템 완전 정합
- 단점: 1-2주 추가 구현, 변형 애니메이션 직접 구현

**옵션 B — MathLive 통합 (Buy):**
- URL: https://cortexjs.io/mathlive
- 장점: 검증된 인터랙티브 수식 편집기, 2-3일 통합
- 단점: 디자인 커스터마이징 한계 가능, 의존성 증가

**결정 절차:** 1주차 페이퍼 프로토타입 + 클릭 데모 단계에서 두 옵션 비교 평가 후 결정. 명세 작성자 동의 필요.

### 9.2.2 Fingerprint 라이브러리

**옵션 A (V1 채택):** UUID v4 + localStorage + 보조 신호 hash (canvas, font 메트릭)
- 단점: 시크릿 모드 / 클리어 시 손실

**옵션 B (V2 검토):** Magic link (이메일 1회 입력) → fingerprint와 합침
- 장점: 시크릿/클리어에도 데이터 보존
- 단점: 비로그인 흐름 깨짐, 이메일 수집 시 PII 정책 재검토

## 9.4 배포 정책

### V1 배포 흐름

```
PR 생성 → GitHub Actions
  ├ TypeScript 타입체크
  ├ ESLint 검사
  ├ 단위 테스트 (Vitest 또는 Jest)
  ├ E2E 테스트 (Playwright, Vercel Preview URL 대상)
  ├ 번들 사이즈 측정 (@next/bundle-analyzer)
  │   └ initial JS gzipped 300KB 초과 시 차단
  └ Vercel Preview URL 자동 생성

main 머지 → Vercel prod 자동 배포
```

### 환경

- **Production**: `games.pullim.ai` (`main` 브랜치 연동) / **dev**: `dev-games.pullim.ai` (`dev` 브랜치 연동) — 2026-06 결정 (근거: `proc/plan/2026-06-23_domain-branch-topology.md` — G1 결정)
- **Preview**: Vercel 자동 생성 URL (PR마다)
- **Local Dev**: `localhost:3004` (포트 고정 — `bun run dev` / `bun run start` 모두 `-p 3004`)

### 배포 정책 핵심 규칙

- **머지 차단 게이트**: 타입체크 실패, 테스트 실패, 번들 사이즈 초과, 회귀 테스트 누락
- **Critical gap 4개에 대한 회귀 테스트는 머지 전 필수**: AST equivalent form, fingerprint 손실, 빈 큐 처리, hit-test 정확도
- **PR 단위 디바이스 smoke test**: 갤럭시 A 시리즈, 아이폰 SE급. 자동화 가능한 부분은 Playwright 디바이스 에뮬레이션, 수동 검증은 마일스톤 단위
- **Hot-fix 정책**: V1 main 직접 푸시 금지. 항상 PR 경로

## 9.7 코드 구조 (멀티게임 V1, 병렬 개발 대응)

상세 설계 근거: [proc/plan/2026-05-08_parallel-game-architecture.md](../plan/2026-05-08_parallel-game-architecture.md)

**모노레포 구조 (2026-06 전환)**: 앱은 `apps/games/` (Turborepo, planner/Q 동형). 앱 내부에 **`src/` 래퍼 없음** — `app`·`components`·`games`·`lib` 직접. 루트엔 `package.json`(workspaces)·`turbo.json`·`tsconfig.base.json`; dev/build/test 는 루트 turbo. backend·packages 미생성(thin — BE 는 별 repo `pullim-api`). 근거: [proc/plan/2026-06-17_monorepo-restructure.md](../plan/2026-06-17_monorepo-restructure.md), [proc/plan/2026-06-22_drop-src-wrapper.md](../plan/2026-06-22_drop-src-wrapper.md).

```
apps/games/                          # 앱 본체 (@pullim-games/games, 포트 3004)
  app/
    layout.tsx                       # 루트 레이아웃
    globals.css                      # Tailwind + Pretendard
    page.tsx                         # / 메인페이지 (registry 조회)
    games/[gameId]/page.tsx          # 동적 라우팅 (manifest.loadComponent) + not-found.tsx
    api/event/route.ts               # POST 이벤트 로깅
  components/                        # 모든 게임 공유 UI (GameCard/ 등)
  lib/
    core/                            # ⭐ Read-only 계약 — 게임은 의존만, 수정 X
      fsrs/ fingerprint/ schema/ ui/ index.ts   # SRS·익명식별·zod·primitive·barrel
    games/
      types.ts                       # GameManifest, GameMeta 인터페이스
      registry.ts                    # ✅ generated 파일 re-export
      registry.generated.ts          # ⭐ scripts/generate-registry.ts가 작성 (commit O)
  games/                             # ⭐ 각 게임 = self-contained 모듈
    factorization/
      manifest.ts                    # ⭐ 자동 발견 대상 (GameMeta + loadComponent)
      component.tsx                  # 게임 entry
      components/ state/ logic/ content/cards/ tests/ README.md
  scripts/
    generate-registry.ts             # ⭐ glob games/*/manifest.ts → lib/games/registry.generated.ts
```

**게임 추가 절차 (중앙 파일 수정 0):**
1. `apps/games/games/<id>/` 디렉토리 생성 + `manifest.ts` 작성 (GameMeta + loadComponent)
2. `apps/games/games/<id>/component.tsx` 작성
3. 끝. 다음 `bun run dev` / `bun run build` 시 `predev`/`prebuild` 훅이 자동으로 registry 갱신.

**머지 충돌 방지:**
- `registry.generated.ts`는 alphabetical 정렬 → 여러 게임 PR이 같은 파일을 수정하지만 충돌 거의 없음
- CI가 `git diff --exit-code registry.generated.ts` 검증해서 manifest와 generated 불일치 차단

**공유 인프라 격리 (`apps/games/lib/core/`):**
- 게임은 `import { ... } from "@/lib/core"` 만 허용 (barrel import)
- internal 파일 직접 import 금지 (ESLint 규칙 — Phase R3에 도입)
- `lib/core/` 변경 = 별도 PR + 모든 게임 테스트 자동 실행

**콘텐츠 영역 max-w 정책 (2026-05-11 추가 — `proc/plan/2026-05-11_layout-overhaul.md` 참조):**

| 페이지 타입 | max-w | 정렬 | 비고 |
|---|---|---|---|
| 홈 (`/`) | 720px | 중앙 | 빈 우측 컬럼 회피, 데이터 신호 충분해질 때 풀폭 재검토 |
| 게임 허브 (`/games`) | 1280px (shell 외곽) | 풀폭 그리드 | 카드 그리드는 넓을수록 자연 |
| 게임 페이지 (`/games/<id>`) | 640~720px (GameShell) | 중앙 | aside prop 없으면 split 도 단일 컬럼 |
| 관리 (`/manage/*`) | 1280px (shell 외곽) | 풀폭 | 데이터·표 위주 |

**Chrome 분기 (AppShell variant):**
- `default`: 헤더(검색/알림/프로필) + 사이드바(lg+ 전체, md 축약) + breadcrumb
- `game`: 헤더 minimal(✕ + 로고만), 사이드바·breadcrumb 미렌더. `/games/<id>` 자동 적용.
