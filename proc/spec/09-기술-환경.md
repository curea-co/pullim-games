### 9.2.1 인터랙티브 수식 렌더 (1주차 결정)

**옵션 B — MathLive 통합 (Buy):**
- URL: https://cortexjs.io/mathlive
- 장점: 검증된 인터랙티브 수식 편집기, 2-3일 통합
- 단점: 디자인 커스터마이징 한계 가능, 의존성 증가

**결정 절차:** 1주차 페이퍼 프로토타입 + 클릭 데모 단계에서 두 옵션 비교 평가 후 결정. 명세 작성자 동의 필요.

### 9.2.2 Fingerprint 라이브러리

**옵션 A (V1 채택):** UUID v4 + localStorage + 보조 신호 hash (canvas, font 메트릭)

(Vercel KV 아님 — auth가 이미 Postgres 채택, spec/05 §5.3·§5.5·§5.6 정합) **⚠️ 2026-07-04 개정(SSO 위임) — 저장 위치는 games 전용 Postgres 그대로 존치**(pullim-api 이관·`DATABASE_URL` 폐기 아님). ⚠️ **키 모델(단일 명시 — Codex #140)**: **내부 저장/조인 키는 games `users.id`(무변경)**. pullim `sub` 는 **PK 가 아니라 외부 신원 매핑 컬럼**(`users.sub UNIQUE`)이다 — `/games/me` 가 준 `sub` 를 첫 진입 시 로컬 `users` row 로 lazy upsert(projection)하고, 이후 모든 `/api/sync`·`fingerprint_links`·조회 쿼리는 **`sub → users.id` 로 resolve 한 뒤 `user_id` 로 동작**한다(FK `user_id REFERENCES users(id) ON DELETE CASCADE` `migrations/0002_learning_data.sql` 무변경). `users.id = sub` 로 통일하지 않는다(legacy row 는 games 생성 id 라 id 타입 혼용 방지). ⚠️ 현행 `users.email`·`password_hash` 는 `NOT NULL` 이라 **projection 성립에 스키마 마이그레이션 선행**: `email`·`password_hash` **NULL 허용** + `sub TEXT UNIQUE`(nullable) 신설, CHECK 로 "(email+password_hash) XOR sub" 보장(pullim projection row=sub 만, legacy row=email+pw). `/api/sync` 충돌머지 semantics 무변경, 신원 매핑 컬럼·projection 계약만 변경(PR-2 에서 확정). 중앙 계정 삭제 전파는 §5.6 파기 계약 참조. 근거: `proc/plan/2026-07-03_games-unified-login-os-delegation.md` D3. |
| 회원 학년 (`grade`) | 게스트=localStorage(`pullim-games:player`) / **회원(legacy)=이미 games Postgres `users.grade` 서버 저장**(가입 시 `createUser(..., grade)`·`0003_user_grade.sql`, 현행) | **2026-07-05 grade 분리 = "서버 저장 도입"이 아니라 games-side 존치 확정 + pullim 회원 확장**: grade 는 콘텐츠 preference(identity PII 아님, `§5.2⒜⑵·§5.5·§5.6`)라 pullim-api 이관 안 하고 games `users.grade` 존치. **legacy 회원은 현행대로 가입 시 저장**. **pullim 회원**은 projection row(`sub` 매핑)의 `grade` 사용 — 단 중앙 signup 미수집이라 games 가 post-login 자체 수집(별도 UX, PR-2), ⚠️ projection row 수용은 PR-2 스키마 마이그레이션(email/pw nullable+sub) 선행. 보존=계정 유효 무기한·변경 overwrite·삭제 시 row 파기(§5.5) |
| Session | localStorage + 서버 이벤트 로그 | Vercel KV 영구 |
| Event 로그 | `/api/event` POST → Vercel Analytics + 별도 분석 DB 검토 | 동일 (확장만) |

#### 통합 로그인(SSO) env (2026-07-04 개정 — §5.2 회원 신원 중앙 위임)

pullim-web/pullim-api SSO 연동은 **env 토글**로 pullim 모드↔legacy 모드를 가른다(`proc/plan/2026-07-03_games-unified-login-os-delegation.md`). ⚠️ **두 env(`NEXT_PUBLIC_DOMAIN_API_URL` + `NEXT_PUBLIC_PULLIM_LOGIN_ORIGIN`)는 all-or-nothing**: 둘 다 있어야 pullim 모드 on, 둘 다 없으면 legacy 유지, **한쪽만 설정 시 부팅 fail-fast**(introspection 은 켜졌으나 미인증 리다이렉트 URL 부재 → 런타임 붕괴 방지).

| env | dev | prod | local (SSO 검증 모드) | 용도 |
|---|---|---|---|---|
| `NEXT_PUBLIC_DOMAIN_API_URL` | `https://dev-api.pullim.ai` | `https://api.pullim.ai` | `http://api.pullim.local:<api-port>` | 회원 세션 introspection(`/games/me`)·직접 호출 base. **아래 LOGIN_ORIGIN 과 함께 있을 때만 pullim 모드 on**(단독 설정=부팅 fail-fast, 위 all-or-nothing 규칙) |
| `NEXT_PUBLIC_PULLIM_LOGIN_ORIGIN` | `https://dev.pullim.ai` | `https://pullim.ai` | `http://pullim.local:3001` | 미인증 회원 리다이렉트 대상 = **SITE 호스트**(`/login?next=`). ⚠️ OS 호스트(`*-os`) 아님 |

- ⚠️ **로컬 host 체계 — 두 모드 명시 분리(Codex #140)**: ⒜ **기본 로컬 dev(비 SSO·legacy)** = games `http://localhost:3004`(포트 고정 `-p 3004`), pullim 모드 env 미설정. ⒝ **로컬 SSO 검증 모드** = games·api·web 를 **`*.pullim.local` 로 통일**(`/etc/hosts` 에 `127.0.0.1 pullim.local os.pullim.local api.pullim.local games.pullim.local`) — games 를 `http://games.pullim.local:3004` 로 띄우고 위 표 local 값 사용. **⚠️ `localhost` 서브도메인은 Chrome 이 eTLD 로 취급해 쿠키 SSO 불가**하므로 SSO redirect/쿠키 회귀 재현은 반드시 `pullim.local` 계열로. bare `localhost` 와 `pullim.local` 을 한 플로우에 혼용 금지.
  - **⚠️ 쿠키 도메인(로컬 SSO 성립 조건)**: 세션 access 쿠키가 `games.pullim.local` 에서 서버측으로 읽히려면 **pullim-api 로컬이 쿠키를 `Domain=.pullim.local`(부모, prod `.pullim.ai` 미러)로 발급**해야 한다 — host-only(`api.pullim.local` 전용) 쿠키면 sibling `games.pullim.local` 이 못 읽어 회원 게이트가 깨진다(prod `Domain=.pullim.ai` 와 동형). 이는 **pullim-api 로컬 config** 사안(운영/핸드오프 관할). bare `localhost` 단일 host 모드에선 이 문제가 없지만(same host) 서브도메인 SSO 재현이 안 되므로, SSO 검증은 반드시 ⒝ 모드 + `.pullim.local` 쿠키로. (pullim-api `CORS_LOCAL_ORIGINS` 에 `http://games.pullim.local:3004` 추가도 필요 — 운영 관할.)
- ⚠️ **prod 승격 함정 — 교차 repo 준비(games env 반쪽은 fail-fast 가 차단)**: games 두 env 는 all-or-nothing fail-fast 라 "로그인만 되고 데이터 깨짐" 같은 **games 내부 반쪽 설정은 부팅에서 걸린다**(런타임 도달 불가). 남는 함정은 **games env 는 완전 설정(pullim 모드 on)인데 다른 repo 의 prod 준비가 안 된 경우** — pullim-api prod CORS(`games.pullim.ai`) 미등록 시 introspection/직접호출 실패, pullim-web resolveNext prod 미배포 시 로그인 후 복귀 실패. 따라서 main 승격 전 **games prod env(둘 다) + pullim-api prod CORS + pullim-web resolveNext prod 3종을 함께** 확인(plan §7).
- CORS: pullim-api 배포 env `CORS_ALLOWED_ORIGINS`에 `dev-games.pullim.ai`(dev)·`games.pullim.ai`(prod) 등록은 pullim-api/운영 관할(games repo 밖).
- **Local Dev 포트**: `localhost:3004` 고정(`bun run dev` / `bun run start` 모두 `-p 3004`). SSO 검증 시 `games.pullim.local:3004` 로 동일 포트 매핑.

## 9.7 코드 구조 (멀티게임 V1, 병렬 개발 대응)

상세 설계 근거: [proc/plan/2026-05-08_parallel-game-architecture.md](../plan/2026-05-08_parallel-game-architecture.md)

**모노레포 구조 (2026-06 전환)**: 앱은 `apps/games/` (Turborepo, planner/Q 동형). 앱 내부에 **`src/` 래퍼 없음** — `app`·`components`·`games`·`lib` 직접. 루트엔 `package.json`(workspaces)·`turbo.json`·`tsconfig.base.json`; dev/build/test 는 루트 turbo. backend·packages 미생성(thin — BE 는 별 repo `pullim-api`). 근거: [proc/plan/2026-06-17_monorepo-restructure.md](../plan/2026-06-17_monorepo-restructure.md), [proc/plan/2026-06-22_drop-src-wrapper.md](../plan/2026-06-22_drop-src-wrapper.md).

```
apps/games/                          # 앱 본체 (@pullim-games/games, 포트 3004)
  app/
    layout.tsx                       # 루트 레이아웃
    globals.css                      # Tailwind + Pretendard
    page.tsx                         # / 메인페이지 (registry 조회)
    games/[gameId]/page.tsx          # 동적 라우팅 (manifest.loadComponent) + not-found.tsx
    api/event/route.ts               # POST 이벤트 로깅
  components/                        # 모든 게임 공유 UI (GameCard/ 등)
  lib/
    core/                            # ⭐ Read-only 계약 — 게임은 의존만, 수정 X
      fsrs/ fingerprint/ schema/ ui/ index.ts   # SRS·익명식별·zod·primitive·barrel
    games/
      types.ts                       # GameManifest, GameMeta 인터페이스
      registry.ts                    # ✅ generated 파일 re-export
      registry.generated.ts          # ⭐ scripts/generate-registry.ts가 작성 (commit O)
  games/                             # ⭐ 각 게임 = self-contained 모듈
    factorization/
      manifest.ts                    # ⭐ 자동 발견 대상 (GameMeta + loadComponent)
      component.tsx                  # 게임 entry
      components/ state/ logic/ content/cards/ tests/ README.md
  scripts/
    generate-registry.ts             # ⭐ glob games/*/manifest.ts → lib/games/registry.generated.ts
```

**게임 추가 절차 (중앙 파일 수정 0):**
1. `apps/games/games/<id>/` 디렉토리 생성 + `manifest.ts` 작성 (GameMeta + loadComponent)
2. `apps/games/games/<id>/component.tsx` 작성
3. 끝. 다음 `bun run dev` / `bun run build` 시 `predev`/`prebuild` 훅이 자동으로 registry 갱신.

**머지 충돌 방지:**
- `registry.generated.ts`는 alphabetical 정렬 → 여러 게임 PR이 같은 파일을 수정하지만 충돌 거의 없음
- CI가 `git diff --exit-code registry.generated.ts` 검증해서 manifest와 generated 불일치 차단

**공유 인프라 격리 (`apps/games/lib/core/`):**
- 게임은 `import { ... } from "@/lib/core"` 만 허용 (barrel import)
- internal 파일 직접 import 금지 (ESLint 규칙 — Phase R3에 도입)
- `lib/core/` 변경 = 별도 PR + 모든 게임 테스트 자동 실행

**콘텐츠 영역 max-w 정책 (2026-05-11 추가 — `proc/plan/2026-05-11_layout-overhaul.md` 참조):**

| 페이지 타입 | max-w | 정렬 | 비고 |
|---|---|---|---|
| 홈 (`/`) | 720px | 중앙 | 빈 우측 컬럼 회피, 데이터 신호 충분해질 때 풀폭 재검토 |
| 게임 허브 (`/games`) | 1280px (shell 외곽) | 풀폭 그리드 | 카드 그리드는 넓을수록 자연 |

**Chrome 분기 (AppShell variant):**
