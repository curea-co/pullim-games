# 03. 핵심 기능 정의

## 3.1 MoSCoW 분류 (V1)

### Must (V1 출시 필수)

- **M1.** **메인페이지 (게임 picker)** — 사용 가능한 게임 모드 목록을 카드 형태로 표시, 각 카드 탭 시 해당 게임 페이지로 이동
- **M2.** **Game Registry 패턴** — 게임을 코드 한 곳(`src/lib/games/registry.ts`)에 추가하면 메인페이지·라우팅·메타데이터에 자동 반영. 새 게임 추가 시 추가 작업 ≤ 1개 파일
- **M3.** **동적 라우팅** `/games/[gameId]` — registry에 등록된 모든 게임이 자동으로 라우팅 가능
- **M4.** **인수분해 블록 분리 메커닉 (V1 첫 게임)** — 다항식이 시각 블록으로 표시, 손가락으로 공통인수를 끌어내면 식이 변형
- **M5.** 5문제 카드 시퀀스 — 난이도 시드 1~5, FSRS 우선순위 큐가 출제
- **M6.** FSRS 백본 (게임 공유) — 모든 게임이 같은 카드 풀과 같은 R/S/D 엔진 사용 (단일 백본 = 다중 모드)
- **M7.** AST 변형 + 정답 판정 — 모든 합법 풀이 경로 인식, equivalent form 매칭
- **M8.** 익명 fingerprint 기반 사용자 식별 — 비로그인, 같은 브라우저 세션 유지
- **M9.** 익명 이벤트 로깅 — drag-start, drag-end, transform, submit, abandon
- **M10.** 모바일 웹 — 카톡/인스타 링크 진입 30초 내 첫 게임 시작 (메인페이지 또는 직접 게임 URL)
- **M11.** OG 카드 — 카톡/인스타/트위터 공유 시 다항식 블록 시각 + 한국어 CTA (게임별 OG 가능)
- **M12.** 5문제 완료 화면 — 차분한 요약 + "한 번 더" / "다른 게임" / "오늘은 끝" 분기

### Should (V1에 들어가면 좋음)

- **S1.** 다크모드 자동 대응 (`prefers-color-scheme`) — V1은 light 디자인이지만 자동 inversion만 — 정식 다크 디자인은 V2
- **S2.** 빈 큐 처리 UI — "오늘은 더 할 게 없어요" 차분한 메시지 + 다음 학습 가능 시간 표시
- **S3.** 부분 정답 처리 — 한 단계만 풀고 멈췄을 때 다음 단계 hit zone 자동 강조

### Should (V1.5 출시 후보)

상세: [proc/plan/2026-05-08_game-lineup-and-filtering.md](../plan/2026-05-08_game-lineup-and-filtering.md) §5

- **S1.** `math-quick-quiz` — 수학 전 단원 빠른 4지선다, 30초 세션 (multiple-choice / shallow)
- **S2.** `english-order` — 영어 어순 맞추기 (sorting / medium / 2분)

### Could (V2~V3 이후 검토)

- **C1.** **V2 게임 4개** — `history-timeline` (사회/sorting), `english-word-match` (영어/matching), `chemistry-balance` (과학/manipulation), `vocab-typing` (국어/typing)

- **W4.** 결제, 멤버십, 광고
- **W5.** 전과목 라인업

- **W7.** AI 자동 메커닉 생성기
- **W8.** 인강/AI 튜터 연동 (V1은 굳히기 전용)

## 3.2 Sitemap

```
/ (메인페이지 — 게임 picker)
  ├ 등록된 게임 목록 (카드 형식)
  └ 각 카드 → /games/[gameId] 진입
/games/[gameId] (게임 플레이 페이지, 동적 라우팅)
  ├ 5문제 카드 시퀀스
  ├ 빈 큐 상태 처리
  ├ 5문제 완료 화면 ("한 번 더" / "다른 게임" / "오늘은 끝")
  └ 에러 (네트워크) 상태 처리
/api/event (이벤트 로깅 API)
  └ POST: drag/transform/submit/abandon 이벤트 수집
```

**V1 한정 등록 게임:** `factorization` (인수분해 블록 분리) 1개. 단, 라우팅·registry·메인페이지는 N개 게임 처리 가능 상태로 출시.

추가 페이지(About, FAQ, 가이드 등)는 명세에 들어가지 않는다 — 메인페이지 자체가 게임의 결을 전달해야 한다.

## 3.2.1 Game Registry 계약 (코드 한 곳)

`src/lib/games/registry.ts`에 다음 형태로 게임 등록:

```ts
// 모든 게임이 만족해야 하는 메타데이터 계약
export interface GameMeta {
  id: string;              // URL slug, 예: 'factorization'
  title: string;           // 한국어 제목, 예: '인수분해 블록 분리'
  subject: string;         // 과목, 예: '수학'
  unit: string;            // 단원, 예: '고1 다항식'
  tagline: string;         // 한 줄 설명, 예: '공통인수를 손가락으로 끌어내요'
  estimatedMinutes: number; // 예: 5
  status: 'available' | 'coming-soon';
  ogImagePath?: string;    // 게임별 OG 카드 (V2)
}
```

게임 추가 절차:
1. `src/games/<id>/index.ts` 에 `GameMeta` + 컴포넌트 export
2. `src/lib/games/registry.ts` 에 import + 배열 추가
3. 끝. 메인페이지·라우팅·메타데이터 자동 반영.

## 3.3 IA (Information Architecture)

### / 메인페이지 (게임 picker, 10-15초 체류)

V1 (게임 1-2개) 구조:

- 상단 (10%): 서비스 워드마크 "풀림 게임즈" + 부제 ("푸는 게 곧 배우는 거예요. 오늘은 어떤 게임으로?")
- 섹션 1 — "플레이할 수 있는 게임" (active 게임 그리드, 1-col 모바일 / 2-col sm+)
- 섹션 2 — "곧 만나요" (coming-soon 게임, 있을 때만)
- 하단 InfoNote: "학습 데이터 — 어떤 게임을 풀어도 같은 카드 풀에 쌓여요"

V2 (게임 6~9개) 추가 영역:

- 섹션 0 — "오늘의 추천" 카드 1개 (헤더 직후, FSRS 기반, 일반 카드보다 약간 큼)
- 과목 필터 칩 가로 스크롤 (전체 / 수학 / 영어 / 국어 / 사회 / 과학) — URL `?subject=` 동기화
- 섹션 1/2 가 필터된 결과로 렌더

V3 (게임 10개+) 추가 영역:

- 메커닉 필터 칩 한 줄 추가 (전체 / 조작 / 정렬 / 매칭 / 객관식 / 타이핑) — URL `?mechanic=`
- 두 축 AND 필터링

광고 카피, 기능 나열, 가입 폼 모두 없음. 검색 바·별점·인기순도 없음 (외재 보상 회피).

### /games/[gameId] 게임 페이지

화면을 위→아래로 5개 영역으로 분할 (자세한 레이아웃은 SPEC 04 참조):

1. 상단 (10%): 진행도 `3 / 5` (좌), 종료/메뉴 (우)
2. 캡션 (5%): `공통인수를 찾아 끌어내세요`
3. 메인 영역 (60%): 다항식 블록
4. 드롭 존 (15%): 점선 윤곽, 드래그 시 강조
5. 액션 영역 (10%): "다음 →" (정답 후만 활성)

### 5문제 완료 후 화면

- 오늘 푼 카드 N장, 누적 XP
- 액션 (동등 비중, 줄임 X):
  - **"한 번 더"** — 같은 게임 계속
  - **"다른 게임"** — 메인페이지로 (다른 게임 선택)
  - **"오늘은 끝"** — 종료
- "내일 또 봐요" 보조 카피
- 폭죽/축포 X

## 3.4.1 게임 카탈로그 카드 수 minimum (V1)

각 official 게임은 V1 카탈로그 단계에서 **카드 ≥ 10장** 보유 의무.

| 항목 | 룰 |
|---|---|
| official 게임 카드 minimum | **10장** (V1 카탈로그 단계) |
| custom 게임 (custom-*) | minimum 없음 — 사용자 직접 카드 생성 |
| 신규 official 게임 추가 시 | 등록 시점 10장 이상 |
| 5장 미만은 즉시 audit informational finding | CONVENTION §7.4 양식에 finding 행 |

### 카드 수 부족 시 영향
- FSRS 큐 회전 ≤ 1일 (5장 기준)
- 모든 카드가 즉시 due-soon 으로 진입 → `dueSoonCount` 부풀려짐 (Plan A C7 fix 후에도 빈도 영향)
- 학습 사이클 (간격 반복) 의미 약화

### V1 → V1.5 이행
- 본 룰 정착 시점 (Plan C Phase 3, 2026-05-19) 기준 17 official 게임 중 16개 = 5장
- factorization 만 10장 — 이미 minimum 충족
- 나머지 16 게임 × +5장 = 80장 신규 콘텐츠 작성 (별 콘텐츠 트랙)
- 본 spec 명시 후 새 게임 등록은 자동으로 10장 minimum

근거: 메모리 룰 *학습효과 우선*. FSRS desiredRetention 0.9 기준 5장은 1일 안에 모두 due 회전 → 학습 신호 차별 X.
