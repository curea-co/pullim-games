## 0. 배경 / 결정

사용자 관찰: "로그인 안 하면 메인에 못 들어가야. 입구에서 게스트/회원 구분해서 받아야. arcade는 그렇게 됨."
→ 직전 합의 spec/05 §5.2 "비로그인 우선 + fingerprint 무마찰(신원 없이 즉시 플레이)"를 **arcade 입구 모델로 전환**(G1 결정 2026-06-01).

**arcade 실측 모델(미러 대상)**: middleware 없음. `/hub` 목록은 누구나 보되, **플레이 진입에서 `if (!player) → /start`** — 게스트라도 `/start`에서 닉네임+학년으로 게스트 프로필을 만들어야 플레이. 로그인=회원. 즉 "무마찰"=완전 익명이 아니라 **플레이 전 게스트 신원 생성**.

## 1. 목표 모델 (games 적용)

```
/  (랜딩)  →  [회원가입] /signup   ┐
           →  [로그인]   /login    ┼─ 회원 경로
           →  [게스트로 시작] /start ─ 게스트 경로(닉네임[+학년] → 게스트 프로필 생성)
```
- **신원 = 게스트 프로필(localStorage) OR 로그인 계정.** 둘 중 하나 있으면 "입장한" 상태.
- **게이트(arcade 동형)**: 게임 플레이 진입 + 대시보드(`/home`)는 **신원 필수**. 신원 없으면 `/`(랜딩)로 리다이렉트. 랜딩·게임 허브 브라우징은 열림(개인화만 차이).
- **무마찰 보존(축소)**: 게스트 경로는 **가입 없이** 닉네임[+학년]만 → 즉시 플레이. 이메일/비번 불필요.
- **게스트→회원 승급**: 회원가입/로그인 시 게스트 프로필 + fingerprint를 계정에 연결(기존 `fingerprint_links` 활용).
