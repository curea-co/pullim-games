## Phase 1 — First Impression (홈 `/`)

> *"홈을 보면 메인 카드 하나에 sparkle 아이콘과 '처음 만나는 풀림 게임즈' 한 줄. 화면 우측 절반이 통째로 비어있다. 첫 시선은 사이드바의 + 풀림 게임즈 로고로 갔다가, 그 다음 '오늘도 수고했어요' 헤딩, 그 다음 sparkle 아이콘. 내가 클릭해야 할 메인 CTA는 4번째에야 인지된다. 한 단어로: **비었다**."*

**Page Area Test:**
- 좌측 사이드바 (홈/게임 허브/관리/소개하기) → 명확
- 메인 카드 → 명확
- "전체 게임 허브 보기" 보조 CTA → 명확
- **데스크탑 우측 절반 빈 공간** → 정체 불명 (의도된 여백인지, 미완성인지)
- "오늘도 수고했어요" 헤딩 → 의도 불명 (첫 방문자에게 수고했다고? empty state가 아니라 returning user 메시지처럼 읽힘)

## Phase 2 — Design System (Inferred)

**Fonts** ✅ — Pretendard Variable 단일 family (spec 9.1 부합)

**Colors** ⚠️ — 두 가지 accent 혼재
- **Primary**: mint/jade `rgb(0, 212, 161)` ★ 풀림 브랜드
- **Secondary accent**: `rgb(29, 78, 216)` blue-700 (사이드바 active 등에 사용)
- Neutral: slate-{50,200,400,500,700,900} + off-white `rgb(251, 250, 248)`
- **문제**: mint 브랜드인데 사이드바 active 상태가 blue-700 — 브랜드 컬러를 active에 안 쓴 이유 불명

**Heading scale** ❌ — 위계 충돌
- H1: `24px / 700` (페이지 타이틀)
- H2: 두 가지 사이즈가 같은 H2로 쓰임 — `20px / 600` (추천 카드), `14px / 700` (섹션 라벨 "나만의 게임")
- H3: 두 가지 weight — `16px / 700` (게임 카드 제목), `16px / 400` (필터 라벨)
- **세만틱 H2가 14px**는 시각 위계 역전. 14px 라벨은 H2가 아니라 어떤 caption/eyebrow 처럼 다뤄야 함

**Spacing** — 시각상 `4·8·16·24·32px` 스케일 사용 추정, 일관됨

**Touch targets** ⚠️ — 3개 헤더 인터랙티브 요소가 44px 미만
- `<a>풀림게임즈</a>` 91×**28** px → 모바일 탭하기 작음
- 검색/알림 `<button>` 36×36 px → 44 권장

## Phase 3 — Findings (impact 순)

### 🔴 HIGH-IMPACT

#### F1. 홈 데스크탑 — 우측 절반이 죽은 공간
- **What**: 1280px 뷰포트에서 메인 카드가 좌측 약 720px만 사용, 우측 ~330px가 통째로 빔
- **Why bad**: 첫인상이 "미완성" 또는 "콘텐츠 부족"으로 읽힘. 학습 게이미피케이션 톤과 맞지 않음
- **Where**: [src/app/page.tsx](src/app/page.tsx) 또는 그 안의 home 레이아웃
- **Fix 방향**: ① 콘텐츠 폭 캡 + 중앙 정렬(현재 좌측 stretch라 가정), 또는 ② 우측에 "오늘 진행 중" / "최근 학습" 보조 영역, 또는 ③ 카드를 정중앙 hero로 — 본격 학습 시작을 명령적으로 유도
- **Screenshot**: [01-home-desktop.png](screenshots/01-home-desktop.png)

#### F2. 게임 플레이 — chrome이 그대로 노출돼 몰입 깨짐
- **What**: 4개 게임 모두 사이드바 + 풀림 헤더 + 브레드크럼이 게임 화면 위에 그대로 보임
- **Why bad**: 하이퍼캐주얼 + 5분 학습 게임의 핵심은 "딴 데 보지 말고 한 판"인데, 게임 영역 좌상단·좌측 1/5가 chrome으로 차지됨
- **Where**: [src/app/games/\[gameId\]/page.tsx](src/app/games/[gameId]/page.tsx) + GameShell 컴포넌트
- **Fix 방향**: 게임 모드에서 사이드바 collapse(아이콘 only 또는 hidden), 헤더는 minimal(브랜드만, 검색/알림 제거 또는 게임 종료 X 만 남김), 브레드크럼 제거
- **Screenshot**: [03-factorization-desktop.png](screenshots/03-factorization-desktop.png), [04-quickquiz-desktop.png](screenshots/04-quickquiz-desktop.png)

#### F3. Split 게임 우측 aside slot이 4개 모두 비어있음
- **What**: math-quick-quiz, chemistry-balance, english-word-match, factorization 모두 데스크탑(lg+)에서 우측 컬럼이 빈 흰 공간
- **Why bad**: spec(plan 4.5)에 "split=lg+에서 aside 노출" 정책 있는데 콘텐츠가 없어 결국 "여백을 의도한 듯한 빈 공간"으로 보임. 게임의 호흡감보다 미완성으로 인지됨
- **Where**: GameShell 컴포넌트의 lg breakpoint
- **Fix 방향**: 두 옵션 ① aside slot이 실제로 채워질 때까지 lg에서도 single column max-width로 게임 영역 중앙 정렬, 또는 ② 진행도 + 힌트 토글 + "이런 식이에요" 예시 등 **모든 게임 공통 aside 콘텐츠**를 정의해서 채움
- **Screenshot**: 위 4개 캡처 모두

#### F4. 모바일 한국어 줄바꿈 — "오늘은 어떤 게/임으로 시/작할까/요?"
- **What**: 게임 허브 페이지 모바일에서 H1이 단어 중간에서 강제 줄바꿈
- **Why bad**: 한국어 가독성 치명적. CSS `word-break: keep-all`(또는 `overflow-wrap: break-word` + `word-break: keep-all`) 누락
- **Where**: 글로벌 [src/app/globals.css](src/app/globals.css) 또는 헤딩 컴포넌트
- **Fix 방향**: `body { word-break: keep-all; }` + 헤딩에 `text-wrap: balance` 적용
- **Screenshot**: [02-hub-mobile.png](screenshots/02-hub-mobile.png)

#### F5. CTA 위계 약함 — primary/secondary 차이 미미
- **What**: 홈의 "인수분해 블록 분리부터"(→ 있음, outline)와 "전체 게임 허브 보기"(outline) — 둘 다 회색 outline. 어느 게 primary인지 즉시 모름. 화살표 아이콘 하나의 차이만 있음
- **Why bad**: 메모리 룰 "Don't make me think" 위배. 첫 화면 CTA는 mindless click이어야 함
- **Where**: 홈 페이지 컴포넌트 + Button variant
- **Fix 방향**: primary는 mint 솔리드 fill(브랜드 컬러를 여기 써야), secondary는 outline 또는 텍스트 링크
- **Screenshot**: [01-home-desktop.png](screenshots/01-home-desktop.png)

### 🟠 MEDIUM-IMPACT

#### F6. 게임 카드 CTA 위치 일관성 X
- **What**: factorization → 하단 중앙 / quick-quiz → 하단 우측 / chemistry → 하단 우측 / word-match → 하단 중앙
- **Why bad**: 학습자가 매번 다음 버튼을 눈으로 찾아야 함 (mindless click 깨짐)
- **Fix 방향**: 게임 공통 CTA 영역 정의 — 하단 sticky 또는 game-shell 슬롯
- **Screenshot**: 4개 게임 캡처 비교

#### F7. 게임 페이지 메타 라벨 위치·표기 불일치
- **What**: 인수분해는 라벨 없음 / 퀴즈·화학은 헤딩 위에 작은 라벨 (`고1-인수분해-공통인수` 식 하이픈) / 단어매칭은 헤딩 옆 — 표기와 위치 둘 다 제각각
- **Why bad**: 게임 간 시각 일관성 무너짐. 하이픈 구분(`고1-인수분해-공통인수`)은 사람이 읽기 어려움. 빵부스러기·태그·라벨 패턴 한 가지로 통일 필요
- **Fix 방향**: 헤딩 위 eyebrow chip 한 줄로 통일: `고1 · 인수분해 · 공통인수` (가운뎃점 separator + 일관 위치)

#### F8. 게임 허브 — 뷰 모드 토글 5개 과함
- **What**: grid / list / table / smaller grid / image 5개 아이콘 토글 (현재 14개 게임)
- **Why bad**: 14개 게임에 5가지 레이아웃 옵션은 선택 피로. 메모리 룰 "Omit, then omit again"
- **Fix 방향**: 기본 grid만 두고 토글 제거 (또는 grid + list 2개만)

#### F9. 게임 허브 — 좌측 필터 5개 과함
- **What**: 검색 + 과목/메커닉/깊이/세션 시간/진행도 — 14개 게임에 너무 많음
- **Why bad**: enterprise SaaS dashboard 느낌. 학습자가 "오늘 5분만" 마인드로 들어왔는데 필터링부터 시작
- **Fix 방향**: 검색 + 과목 1개만 노출, 나머지는 "더 보기" 뒤로

#### F10. "1 Issue" 빨간 토스트가 학습 화면 위에 떠있음
- **What**: 좌측 하단 N 아바타 옆에 빨간 "1 Issue" 노티가 게임 허브에 노출
- **Why bad**: 운영 노티가 학습 콘텐츠 위에 노출되면 안 됨. 무엇보다 학습자 페르소나에는 "Issue" 라는 단어 자체가 noise
- **Fix 방향**: 학습자 페이지에서 운영용 widget 제거 또는 dev 환경에서만 노출
- **Screenshot**: [02-hub-desktop.png](screenshots/02-hub-desktop.png)

#### F11. 헤딩 톤 비일관 — 명령형 vs 의문형
- **What**: "공통인수를 찾아 끌어내세요" / "반응식의 균형을 맞춰주세요" / "짝을 맞춰주세요" (명령) ↔ "2x + 4 의 인수분해는?" (의문)
- **Why bad**: 게임 헤딩 톤이 갈림. 학습자는 "지금 뭘 해야 하지?" 를 헤딩에서 즉시 파악해야 함
- **Fix 방향**: 모든 게임 헤딩을 동사 명령형 존댓말로 통일 ("인수분해 형태를 골라주세요")

### 🟡 POLISH

#### F12. 사이드바 active 상태 컬러가 brand mint 아닌 blue-700
- **What**: 메뉴 active 시 잉크블루 — 브랜드 mint와 어울리지 않음
- **Fix 방향**: mint로 통일, 또는 mint underline + neutral text

#### F13. H2 semantic-visual 역전 — `<h2>나만의 게임</h2>` 14px
- **What**: 의미적 H2인데 시각적으로 caption 크기
- **Fix 방향**: 14px section eyebrow는 `<p class="eyebrow">` 또는 별도 컴포넌트로, H2는 시각적으로 H2답게

#### F14. 필터 라벨 H3 weight 400
- **What**: 필터 라벨이 H3인데 weight 400(regular) — 라벨 weight 표준 500+ 미달
- **Fix 방향**: weight 500 또는 600

#### F15. 헤더 인터랙티브 요소 터치 타겟 < 44px
- **What**: 풀림 로고 28px 높이, 아이콘 버튼 36×36
- **Fix 방향**: 모바일 44×44 가이드라인 충족 (히트 영역 padding 확대)

#### F16. "오늘도 수고했어요" 첫 방문 톤 어색
- **What**: 신규 사용자에게 "오늘도 수고했어요"
- **Fix 방향**: empty state 분기 — 첫 방문이면 "5분, 한 판부터 시작해 볼까요"

#### F17. 진행도 표시 약함 — 작은 텍스트 "1/5"
- **What**: 게임 진행도가 회색 작은 텍스트만. 프로그레스 바 없음
- **Fix 방향**: thin progress bar 추가 (mint fill, 4px 두께)
