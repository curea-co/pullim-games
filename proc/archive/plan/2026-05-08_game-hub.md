  - `2026-05-08_management.md` (나만의 게임 데이터 모델)
- **결론 한 줄**: **`/games` = 모든 게임의 통합 진입점. 4 뷰 (그리드/리스트/테이블/썸네일) 토글, 6축 촘촘한 필터, "나만의 게임" 좁은 별도 영역. 게임은 큼지막한 카드뿐 아니라 정보 밀도 높은 표 형태로도 볼 수 있게.**

## 1. 배경 및 사용자 명시 요구

> "게임 허브가 모든 게임을 모아두는 공간. 게임은 카드 형태로 큼지막하게 구성하기만 하지말고 뷰 형태를 전환할 수 있게 구성. 테이블 형태, 그리드 형태, 썸네일 형태로 구성해서 접근. 그리고 필터링도 너무 듬성듬성 조잡하고 어색하게 UI 배치되면 안 돼. 조금은 촘촘할 필요가 있어. 그리고 여긴 '관리' 페이지에서 설정한 나만의 게임을 노출하는 별도의 공간을 제공할 수 있어야 해. 다만, 이 공간은 일반적인 게임들을 보여주는 공간보다는 좁은 공간을 차지해야겠지."

핵심 4가지:
1. 4 뷰 전환 (테이블·그리드·썸네일 + 큼지막한 카드)
2. 촘촘한 필터링 — 듬성듬성·조잡 X
3. 나만의 게임 별도 영역 (좁게)
4. 게임 진입의 단일 hub

## 2. 목표

1. **4 뷰 전환** — 사용 시나리오에 맞춰 정보 밀도 선택
2. **6축 촘촘한 필터** — 과목 / 메커닉 / 깊이 / 시간 / 진행도 / 검색
3. **나만의 게임 영역** — 일반 게임 영역의 30% 이하 폭
4. **현재 진행도 시각** — 게임 카드/행에 푼 카드 비율 직접 표시
5. **URL 쿼리 sync** — 뷰·필터 상태가 URL 에 (공유·뒤로가기)
6. **모바일 우선** — 4 뷰 모두 모바일에서 작동

## 3. 비목표

## 4. 4 뷰 정의

### 4.1 그리드 (Grid) — 기본

큼지막한 카드 2-col (모바일 1-col) — 현재 메인페이지의 GameCard 패턴.
- 카드 안: 아이콘 + 제목 + 과목·단원 + 태그라인 + 시간 + 진행도 바
- 정보 밀도: 낮음, 시각 흡인력 높음
- 사용 시나리오: 처음 진입 / 가볍게 둘러보기

### 4.2 리스트 (List)

세로 스택 행 — 한 줄에 1게임. 카드보다 슬림.
- 좌: 작은 아이콘 + 제목 + 과목 한 줄
- 우: 진행도 + "시작하기" 작은 버튼
- 정보 밀도: 중
- 사용 시나리오: 익숙한 사용자 빠르게 진입

### 4.3 테이블 (Table)

전통적 테이블 — 컬럼 헤더 + 행.
- 컬럼: 아이콘 / 제목 / 과목 / 단원 / 메커닉 / 깊이 / 시간 / 진행도 / 정답률 / 액션
- 정보 밀도: 높음, 비교·필터링 친화
- 모바일: 가로 스크롤 (overflow-x-auto) — 필수 컬럼 (제목·진행도·액션) sticky
- 사용 시나리오: 게임 비교 / 약점 분석

### 4.4 썸네일 (Thumbnail)

작은 정사각 카드 그리드 — 아이콘 중심.
- 5-col (데스크탑), 3-col (태블릿), 2-col (모바일)
- 카드 안: 아이콘 + 제목만 (1-2줄)
- 정보 밀도: 낮음, 한 화면에 많은 게임 노출
- 사용 시나리오: 한눈에 라인업 보기 / 빠른 선택

### 4.5 뷰 전환 토글

페이지 상단 우측에 4 아이콘 토글 (`Grid3x3`, `List`, `Table`, `LayoutGrid` 등).
- 활성 뷰는 jade 강조
- URL 쿼리: `?view=grid|list|table|thumbnail` (기본 grid)
- localStorage 에 마지막 선택 저장 → 다음 진입 시 복원

## 5. 필터 시스템 (6축 촘촘하게)

### 5.1 필터 축 정의

| 축 | 옵션 | 동작 |
|---|---|---|
| **검색** | 텍스트 입력 | 제목 / 단원 / 태그라인 부분일치 (case-insensitive) |
| **과목** | 전체 / 수학 / 영어 / 국어 / 사회 / 과학 | 칩 그룹 |
| **메커닉** | 전체 / 조작 / 정렬 / 매칭 / 객관식 / 타이핑 | 칩 그룹 |
| **깊이** | 전체 / 얕음 / 중간 / 깊음 | 칩 그룹 |
| **세션 시간** | 전체 / ≤1분 / ≤3분 / 그 이상 | 칩 그룹 (estimatedMinutes) |
| **진행도** | 전체 / 시작 안 함 / 진행 중 / 완료 | 칩 그룹 (FSRS state 기반) |

→ 6축 = 검색 + 5 칩 그룹.

### 5.2 UI 배치 (촘촘하게)

#### 데스크탑 (lg+)
페이지 좌측에 sticky 사이드 필터 패널 (220px).
- 검색 input (top)
- 5 그룹 칩 (각 그룹 라벨 + 칩 가로 wrap)
- 하단 "필터 초기화" 버튼

#### 태블릿 (md)
필터 패널을 페이지 상단 collapsible 로 (기본 펼침).
- 검색 + 5 칩 그룹 가로 정렬, 2 줄 wrap

#### 모바일 (<768)
필터 sheet — "필터" 버튼 → drawer 안에 모든 필터.
- 검색은 페이지 상단 항상 노출 (모바일에서도)
- 5 칩 그룹은 sheet 안

### 5.3 적용 후 표시

필터 적용 시 페이지 헤더에 "10개 중 N개 노출 — 필터: 수학·조작" 같은 status bar.
- 적용된 필터를 빠르게 한 번에 해제하는 "전체" 버튼

### 5.4 빈 결과 처리

"이 조합으로는 게임이 없어요" + "필터 초기화" 버튼.

### 5.5 URL 쿼리 sync

```
/games?view=table&subject=math&mechanic=manipulation&depth=deep&search=인수
```

- `useSearchParams` 로 읽기, `router.replace` 로 쓰기
- 공유 / 북마크 / 뒤로가기 모두 작동

### 5.6 정렬

V0.5 는 **단일 정렬 옵션 = "메커닉 결 → 깊이 → 난이도 시드 순"**. 사용자 토글 X.

이유: 게임 10개 규모에 정렬 토글이 인지 부하 추가. V0.6+ 게임 20+ 시점에 재검토.

## 6. 진행도 표시

### 6.1 데이터 source

`home-dashboard.md` §4 의 `computeDashboardStats()` 의 `perGame` 부분 차용.

각 게임 카드/행에:
- `cardsTouched / cardsTotal` (예: 3/5)
- `accuracy` (선택, 깊이 보고 싶은 사용자만 — 테이블 뷰에 노출)

### 6.2 시각

진행도 바 또는 fraction 텍스트:
- 그리드/리스트: 작은 jade 진행 바 + "3/5"
- 테이블: 텍스트 fraction + 정답률 별도 컬럼
- 썸네일: 카드 좌상단에 작은 jade 점 (진행 중) / 가득 찬 점 (완료)

### 6.3 빈 상태

`cardsTouched === 0` 인 게임 = "시작 안 함" 표기. 회색 톤. 아이콘에 "+" 또는 시작 표시.

## 7. 나만의 게임 영역

### 7.1 위치 / 비율

페이지 하단에 **별도 섹션** (일반 게임 그리드 다음).
- 데스크탑: 70% (일반) / 30% (나만의 게임) 가로 분할 검토했으나, **세로 분리** 채택
  - 이유: "나만의 게임"이 일반보다 노출이 약해야 함 + 모바일 친화
- 모바일: 일반 위, 나만의 게임 아래

### 7.2 제목 / 헤더

```
나만의 게임
"관리"에서 만든 카드를 풀어볼 수 있어요  → /manage 링크
```

빈 상태 (커스텀 게임 0개): "관리에서 첫 번째 카드를 만들어 보세요" + CTA → /manage/content

### 7.3 시각 차별

- 일반 게임 카드: jade accent
- 나만의 게임 카드: 보라/연한 분홍 등 부 색상 — V0.5 디자인 검토 (구현 시 정확한 색 결정)
- 제목 영역에 작은 "MY" 뱃지 또는 사용자 이름 영역

### 7.4 데이터 model 의존

`management.md` 에서 정의될 사용자 콘텐츠 → 커스텀 카드 → 커스텀 게임 매핑.

**본 plan 은 영역 자리만 잡음**. 실제 커스텀 게임 데이터 fetching·표시는 `management.md` 와 함께 V0.5 H 단계에서 합쳐 구현.

빈 영역만 placeholder 로 마무리해도 OK (커스텀 게임 0개 빈 상태).
