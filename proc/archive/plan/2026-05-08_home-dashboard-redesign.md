## 1. 기존 구현의 문제

`proc/archive/plan/2026-05-08_home-dashboard.md` 결과:

| 영역 | 기존 구현 | 사용자 의도와 갭 |
|---|---|---|
| KPI | "진행한 게임 N개", "정답률 M%", "오늘 풀이 N장" | 정답률은 비율 — 절대적 성공·실패 횟수가 아님. 사용자는 "**얼마나 성공, 얼마나 실패**" 라는 절댓값 표현 |
| 게임별 진행 | 단일 행에 "5장 중 3장 · 정답률 67%" | 진행도와 정답률만, **성공·실패 카운트 없음**. 시각도 평범한 행 |
| 시각 위계 | 모든 게임 동등한 슬림 행 | 한눈에 "이 게임은 잘했고, 저 게임은 어렵다" 가 안 잡힘 |

사용자 평가:
> "내가 제안했던 내용이 단 한개도 안들어가있네"

**핵심**: 사용자가 원하는 건 **게임 단위 성과의 절대적 가시성**. 정답률·진행도 같은 비율은 추상적, 직관적이지 않음.

## 2. 사용자 의도 재해석 (재기획 전)

> "현재 사용자가 어떤 게임을 얼마나 성공했고, 얼마나 실패했고, 몇 개의 게임을 진행했는지 확인할 수 있는 일종의 대시보드"

세 가지 정보 명시:

1. **어떤 게임** — 게임 단위가 1차 분류 (KPI 합산이 아님)
2. **얼마나 성공** — 절대 카운트 (예: "12번 성공")
3. **얼마나 실패** — 절대 카운트 (예: "3번 실패")
4. **몇 개의 게임 진행** — 게임 다양성 (n / 14 같은 분모 포함)

→ 홈의 **시각 단위 = 게임 카드**. 카드 안에 성공·실패 절댓값 큼지막하게.

## 3. 목표

1. **게임별 성공·실패 절댓값을 카드 단위로** 한눈에 노출
2. **게임 다양성** (몇 개 게임 진행했나) 별도 강조
3. **공식 + 커스텀 게임 통합 표시** — 둘 다 진행 가능
4. **시각 위계** — 가장 많이 푼 게임을 카드 큼지막하게, 안 풀어본 게임은 작거나 흐릿
5. **외재 보상 회피 일관** — 점수·랭크·뱃지·콤보 어휘 0
6. **빈 상태 친절** — 진행한 게임 0 = "처음 만나는" 카드 + factorization 추천

## 5. 데이터 모델 (변경)

기존 `DashboardStats` 의 `accuracy`, `totalAttempts`, `totalCorrect` 필드는 그대로 두되, **PerGameStat 보강**:

```ts
// 변경 전
interface PerGameStat {
  gameId: string;
  title: string;
  cardsTouched: number;
  cardsTotal: number;
  attempts: number;
  correct: number;
  accuracy: number;
  lastReviewAt?: Date;
}

// 변경 후 — 명시 필드 추가
interface PerGameStat {
  gameId: string;
  title: string;
  cardsTouched: number;
  cardsTotal: number;
  attempts: number;
  /** 정답 횟수 (성공) — UI 에 큼지막한 숫자로 노출 */
  correct: number;
  /** 오답 횟수 (실패) = lapses 합 */
  failed: number;
  accuracy: number;
  lastReviewAt?: Date;
  /** 게임 분류 — UI 에 official/custom 구분 */
  kind: "official" | "custom";
  /** lucide 아이콘 (manifest 직접 참조) */
  icon: GameMeta["icon"];
}
```

→ `failed` 필드를 명시 추가 (기존엔 attempts - correct 로 추론 가능했지만 UI 에 1차 라벨로 쓰려고).

## 6. UX 재설계

### 6.1 화면 IA (모바일 우선)

```

├──────────────────────────────────────┤

│ └─────────────────┘                  │

│ │ ⚡ 수학 빠른퀴즈  │                  │

│ └─────────────────┘                  │

│ │● │● │● │● │  ← 썸네일 그리드      │
```

### 6.2 위젯 구성 (재설계)

#### A. Header (변경 작음)
- 시간대별 인사 (그대로)
- 부제: "N개 게임을 만났어요" — 게임 다양성 1차 표시 (변경: "M장 풀었어요" 대신 게임 수 강조)

#### B. 통합 KPI 2-card (변경 큼)
- 좌: **성공** N번 (큰 숫자, jade glow)
- 우: **실패** M번 (큰 숫자, slate)
- 아래 helper: "오늘 N번"
- ⚠️ **정답률 % 카드 제거** — 게임별 카드에서 보여줌

#### C. 게임별 성과 카드 (재설계 핵심)
- 풀어본 게임 (cardsTouched > 0) 만 노출
- 카드 1개당:
  - 좌상: 게임 아이콘 + 제목
  - **중앙: 성공 N · 실패 M (큰 숫자, 양옆)**
  - 하단: 진행도 바 (jade) + 정답률 부가 표시
  - 카드 클릭 → /games/[id] 진입
- 정렬: attempts 내림차순 (가장 많이 푼 게임이 위)
- 시각 위계:
  - attempts ≥ 10 = 강조 (jade glow border)
  - attempts 1-9 = 일반
  - attempts 0 = 표시 안 됨

#### D. 만나지 못한 게임 (신규)
- cardsTouched === 0 인 게임 모음
- 작은 썸네일 그리드 (4-col 모바일, 6-col 데스크탑)
- 클릭 → /games/[id] 진입
- 헤더: "만나지 못한 게임 N개"
- 게임 다양성 채우기 유도

#### E. 오늘의 추천 (위치 이동)
- 화면 하단으로 이동 (가장 위 → 가장 아래)
- 이유: 게임별 성과가 1차 정보, 추천은 2차 액션
- 카드 형태 그대로

### 6.3 빈 상태 처리

**진행한 게임 0개**:
```
처음 만나는 풀림 게임즈
인수분해 블록 분리부터 시작해요

[ 인수분해 블록 분리부터 → ]
[ 전체 게임 허브 보기 ]
```

대시보드 위젯 모두 숨김 (KPI / 게임별 / 미진행 / 추천 모두 X — 단순 안내만).

### 6.4 데스크탑 (lg+) 레이아웃

- KPI 2-card 가로 (한 행)
- 게임별 성과 = 2-col 그리드
- 미진행 게임 = 6-col 썸네일
- 추천 = 단일 카드 폭 절반

## 7. 시각 톤

### 7.1 외재 보상 회피 (강화)

- 점수·랭크·뱃지·콤보·레벨업·EXP 어휘 사용 0 (기존 plan 동일)
- "성공" / "실패" 라는 단어 자체는 사용 OK — 사용자 의도 그대로
  - 단, "실패" 보다 "다시 만날" 같은 부드러운 톤 검토. 본 plan 채택: **"성공" + "실패" 그대로 명시**, 시각만 절제.
- "정답률" 같은 비율은 부가 정보 (작은 글자)

### 7.2 색

- 성공 숫자 = jade #00D4A1 (강조)
- 실패 숫자 = type-secondary (절제) — accent-negative #F87171 안 씀 (실패에 부정적 시각 강조 회피)
- 카드 강조 = attempts ≥ 10 시 border-accent-positive
- 미진행 게임 = type-secondary opacity-65

### 7.3 숫자 강조

- 성공·실패 숫자는 `text-display` (24px) tabular
- 라벨 ("성공", "실패") 은 `text-helper`
